# Editor Outliner: deep test catalogue

Everything the outline-mode suite (`e2e/CASES.md`, groups M … X) doesn't cover: indent / outdent and move outside
outline mode, which hierarchy a command acts on, Expand / Shrink, node selection on headings, folding, heading guides,
level labels, H7+ styling, drag handles with real mouse drags, Vim mode, where it works (normal tab, Editor Lanes
card, Canvas text and file card, page preview popover, popout window, Source / Live Preview / Reading view, mobile
emulation), settings, keys and hotkey conflicts, IME, several cursors, undo, unloading, console errors, long notes and
typing (`TYPING`).

**Final full run: 2026-11-07 (outline mode always on, Enter leaves a list, code blocks in items)** in an isolated Obsidian 1.15.0 (test vault 948 copy, sandbox 4), real key and mouse input
over the DevTools protocol. Result: `run.mjs` 2221 checks: 2221 pass, 0 fail, 0 error, 0 decide; `extra.mjs` 8 / 8 pass (X1–X4, X6–X9; X10, X11 need --mobile); visual checks pass; TYPING passes.

How the cases run:

- **Key cases** (groups below, ids KI, KM, XS, NS, FC, G, DG, VM, WH, NO) are data in `e2e/cases-deep.mjs`, run by
  `e2e/run.mjs` together with the outline-mode cases (`CASES.md` lists both, generated from them). Notation as in
  `CASES.md`: `|` cursor, `⟦ … ⟧` selection, `↵` a line break and `⇥` a tab in these tables, L*n* a 0-based line.
  "lanes" means an Editor Lanes card in Live Preview and Source mode (the runner's default); "everywhere" adds a normal
  tab (both views), a Canvas text card, a Canvas file card and a page preview popover (Live Preview). "= Obsidian"
  means the same keys with outline mode and the Outliner keys off. After a one-key change in outline mode (and where a
  case says `undo`), one Ctrl+Z must restore the setup text. Every run also checks that Obsidian's renumbering never
  has to change the plugin's result, and lists uncaught exceptions and console errors (`e2e/results.md`).
- **Extra checks** (X1–X10) that aren't keys: `e2e/extra.mjs` (results `e2e/extra-results.md`).
- **Visual checks** (V1–V4): screenshots of the sandbox read by eye.
- The runner's new pieces: a `drag` action (hover, press on the handle, move, optional Escape, release, with Canvas
  iframe zoom accounted for), a `popover` surface, `want: "@obsidian"`, and the console-error log.

Run: `CDP_PORT=<port> node custom-plugins/editor-outliner/e2e/run.mjs [--filter '^(KI|KM|XS|NS|FC|G|DG|VM|WH)[0-9]']`
and `CDP_PORT=<port> node custom-plugins/editor-outliner/e2e/extra.mjs [--mobile]` against a throwaway Obsidian.

Status: PASS / FAIL as of the final run; "fixed" names the issue (D1–D8 below) or the user decision a case found or follows
before it passed.

## Consistency gaps

Implemented (low risk, in the spirit of the spec): D1 (settings and unloading in Canvas cards and popovers), D3 / D4
(Expand's code-lines and callout steps in bodies and callouts as in items), D5 / D6 (Expand, Shrink, indent and move
step aside with IME and several cursors like the other keys), D7 (the fold notice everywhere), D8 (block drops keep the
body's spacing as Move does), and the page preview popover as a tested surface.

Implemented after the user's decisions: item node selection with the Outliner keys whatever outline mode is
(decision 2), the mobile toolbar's indent / outdent routed to the plugin (decision 4). Decided against: heading Move
into the parent's neighbour (1), H7+ styling in Reading view (3).

Still proposed (not implemented): an editor already open when the plugin loads (a Canvas card or popover being edited
at that moment) only gets the plugin when reopened (Obsidian's limitation; see the report).
