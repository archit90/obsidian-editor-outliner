# Editor Outliner: deep test catalogue

Everything the outline-mode suite (`e2e/CASES.md`, groups E … X) doesn't cover: indent / outdent and move outside
outline mode, which hierarchy a command acts on, Expand / Shrink, Home, node selection on headings, folding, no heading guides,
level labels, H7+ styling, drag handles with real mouse drags, Vim mode, where it works (normal tab, Editor Multiple Lanes
card, Canvas text and file card, page preview popover, popout window, Source / Live Preview / Reading view, mobile
emulation), working with other plugins, settings, keys and hotkey conflicts, IME, several cursors, undo, unloading,
console errors, long notes and typing (`TYPING`).

**How to run**, in a throwaway Obsidian on its own virtual display (SPEC.md → Development → End-to-end tests):

- **Alone**, in a fresh vault with only this plugin: `npm run build && e2e/sandbox.sh reset 4 && npm run e2e`
  (`e2e/run.mjs`, the key cases, then `e2e/extra.mjs`, the other checks; `--mobile` for X10 / X11). Cases that need
  another plugin are skipped: the Editor Multiple Lanes card surface and the LC cases, and WH11 (Dataview).
- **Together** with Editor Multiple Lanes (its build folder, or its release `archit90/obsidian-editor-multiple-lanes`),
  in a separate sandbox state: `npm run e2e:cases` with `OBS_PLUGINS=<folder> OBS_SANDBOX_DIR=$PWD/.sandbox-together`
  for `e2e/sandbox.sh reset 4`, and `E2E_REQUIRE=editor-multiple-lanes` so a missing Lanes fails instead of
  skipping; `--surfaces lanes` runs just the card surface. Dataview the same way (`blacksmithgu/obsidian-dataview`).
- One case or group: `node e2e/run.mjs --filter '^(KI|KM)[0-9]'`; the catalogue: `npm run e2e:catalogue`.

**Together with Lanes, 2026-11-09:** `--surfaces lanes`: 263 checks, 262 pass, 1 flaky (`e2e/results-together.md`).
MB2's one-Ctrl+Z check in a lanes card fails about once in 10–25 runs (the same focused editor, the Ctrl+Z changes
nothing; cause not found): the runner then runs the case once more and records FLAKY if that passes.

**Final runs: 2026-11-09** (with the Home cases, HM), Obsidian 1.15.0 in a sandbox, real key and mouse input over the
DevTools protocol:

- **Alone** (a fresh vault, only this plugin): `run.mjs` 2294 checks: 2108 pass, 0 fail, 0 error, 186 skipped
  (the lanes card surface: 185, and WH11: Dataview); `extra.mjs --mobile` 12 / 12 (X1–X4, X6–X12).
- **Together with Editor Multiple Lanes** (its folder build; `--surfaces lanes`, `E2E_REQUIRE=editor-multiple-lanes`):
  263 checks, 262 pass. MB2's one-Ctrl+Z check (Insert Dataview query from the palette, in a card) failed once and
  passed when the case ran again: flaky in a long run (not chased further).
- TYPING passes; the visual checks were last read on 2026-11-08 (not repeated on 2026-11-09). Before the 2026-11-08 changes, at 20,000 lines: Enter split +11.5 ms over
  Obsidian's own Enter (now +0.9), Backspace merge +13.8 ms (now +7.6), a move 29.8 ms (now 20.1).

How the cases run:

- **Key cases** (groups below, ids KI, KM, XS, HM, NS, FC, G, DG, VM, WH, NO, OP, LC) are data in `e2e/cases-deep.mjs`, run
  by `e2e/run.mjs` together with the outline-mode cases (`CASES.md` lists both, generated from them). Notation as in
  `CASES.md`: `|` cursor, `⟦ … ⟧` selection, `↵` a line break and `⇥` a tab in these tables, L*n* a 0-based line.
  "tab" means a normal tab in Live Preview and Source mode (the runner's default); "lanes" an Editor Multiple Lanes
  card (Live Preview and Source mode; needs that plugin); "everywhere" is a tab, a lanes card, a Canvas text card, a
  Canvas file card and a page preview popover (Live Preview). "= Obsidian" means the same keys with outline mode and
  the Outliner keys off. After a one-key change in outline mode (and where a case says `undo`), one Ctrl+Z must
  restore the setup text. Every run also checks that Obsidian's renumbering never has to change the plugin's result,
  and lists uncaught exceptions, console errors and the plugin's warnings (`e2e/results.md`).
- **Fixtures:** each runner makes its own notes (`_test/e2e*.md`, `_test/tab/…`, `_test/e2e.canvas`) and restores
  every setting it changes; `e2e/make-vault.mjs` sets the editor settings the cases are written for (tabs of size
  4, no readable line length) and turns Canvas and Page preview on. With Editor Multiple Lanes enabled, the runners
  turn its `lanesOnly` on and add `_test/tab/` to its routing exceptions, and put both back at the end.
- **Extra checks** (X1–X12) that aren't keys: `e2e/extra.mjs` (results `e2e/extra-results.md`).
- **Visual checks** (V1–V4): screenshots of the sandbox read by eye (`e2e/sandbox.sh shot 4 <absolute path>`).

Status: PASS / FAIL as of the final run; "fixed" names the issue (D1–D15 below) or the decision a case found or follows
before it passed.

## Consistency gaps

Implemented (low risk, in the spirit of the spec): D1 (settings and unloading in Canvas cards and popovers), D3 / D4
(Expand's code-lines and callout steps in bodies and callouts as in items), D5 / D6 (Expand, Shrink, indent and move
step aside with IME and several cursors like the other keys), D7 (the fold notice everywhere), D8 (block drops keep the
body's spacing as Move does), and the page preview popover as a tested surface.

Implemented after the user's decisions: item node selection with the Outliner keys whatever outline mode is
(decision 2), the mobile toolbar's indent / outdent routed to the plugin (decision 4). Decided against: heading Move
into the parent's neighbour (1), H7+ styling in Reading view (3); kept as is: Cmd+↑ / ↓ on macOS (5).

Still proposed (not implemented): an editor already open when the plugin loads (a Canvas card or popover being edited
at that moment) only gets the plugin when reopened. Obsidian's `registerEditorExtension` reaches only the editors of
Markdown views; reaching the others would mean finding them through Canvas and popover internals.
