# Editor Outliner: review findings

The findings of the code reviews, by id, so the ids that unit tests and comments carry (`EO-03` …) resolve here.
The status is as of now; SPEC.md says how the plugin behaves.

## Review of 2026-11-06 (EO-01 … EO-42)

Correctness, Obsidian internals (checked against 1.15.0), performance at 20,000 lines, data safety and UX. Every
finding was checked against the source before it was fixed; the regression tests named after an id are in
`src/outline.test.ts`.

## Review of 2026-11-08 (before the repository stood alone)

What changed after it (tests in `src/perf.test.ts`, `src/rowdiff.test.ts`, `src/settings.test.ts`,
`src/numbering.test.ts`; e2e cases KM19, G14, WH14, OP1–OP3, LC1–LC6, X9 / X9b, X12):

- `%%`, `$$` and `<!--` inside inline code opened a comment or math block to the end of the note; a move above
  such a line then took the rest of the note along.
- Every list-editing key cost the note's length several times over (parses and whole-note copies); typing in a
  heading line re-parsed the note on every keystroke; the palette's availability checks ran whole operations;
  Shift+Tab's "a list stays a list" check was quadratic.
- A paste the outliner takes now goes to other plugins' `editor-paste` handlers first, as Obsidian's paste does.
- Missing Obsidian internals are reported on load; renumbering is checked against a table recorded in Obsidian.
- Smaller: a closed editor kept as the last focused one, settings loaded without checking their types, an
  unfinished reconfigure on unload, an IME composition disturbed by a deferred redraw, stale comments.
